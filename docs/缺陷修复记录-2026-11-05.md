## 二、逐条修复说明

### D-01 采集写入 NaN 导致入库失败、任务卡死（高）

现象：采集任务 `single:market_summary` 全部失败，报 `Invalid JSON text: "Invalid value." ... for column 'market_daily.extra'`，且相同批次的阶段日志永久停在 `running`。

根因：
1. `backend/app/collectors/market.py` 用 `float(取值 or 0)` 拼装快照，遇到数据源返回的空值会得到 `NaN`，`NaN` 被写入 `market_daily.extra`（MySQL JSON 列）时被拒绝。
2. 写入异常发生时，任务/阶段日志未做终态化处理，因此长期停在 `running`。

修复：
- `backend/app/collectors/util.py` 新增 `is_bad_number` / `safe_float` / `safe_int` / `json_safe`。
- `market.py` / `moneyflow.py` / `news.py` / `kline.py` / `finance.py` 全线接入安全数值与 JSON 安全化，脏值统一转为 `None`。
- `backend/app/services/market.py` 的 commit 包上 try/except，异常时回滚。
- `backend/app/services/pipeline.py` 新增 `_finalize_log`，确保任务与阶段日志无论成功失败都落到终态，不再卡 `running`。

实测：飞牛 `single:market_summary` → 任务终态 `success`，无 JSON 报错；`single:moneyflow` → 终态 `success`。

### D-02 akshare 版本漂移（高）

现象：`moneyflow` 报 `module 'akshare' has no attribute 'stock_fund_flow_market'`；`news` 报 `... no attribute 'stock_telegraph_cls'`，两条线始终无数据。

根因：业务代码调用的 akshare 函数在新版本中已不存在（改名/移除），属版本漂移。

修复：
- `moneyflow.py` 改用 `stock_market_fund_flow()`（实测无 NaN）。
- `news.py` 改用 `stock_info_global_cls(symbol="全部")`，并做发布时间规整。
- `backend/requirements-data.txt` 锁定 `akshare==1.20.27`，避免再次漂移。

实测：飞牛 `moneyflow` 主源 0.5s `ok=True count=1`；`news` 主源 1.8s `ok=True count=11`，资讯实际入库 9 行。

### D-03 timeout_sec 未生效（高）

现象：数据源配置的 `timeout_sec`（如 60 秒）不起作用，`market_summary` 主源实测挂起 78 秒以上仍不返回。

根因：采集调用未接入超时控制，长挂起请求没有上限。

修复：
- 新增 `backend/app/utils/timeout.py`，提供 `call_with_timeout(fn, timeout_sec)`。
- `backend/app/collectors/base.py` 重写为实例方法 `test_connection`，并接入超时。
- `backend/app/services/source_registry.py` 的 `call_source` / `probe_source` 统一走超时执行。

实测：飞牛 `market_summary` 主源（60s）在 60.3 秒即返回 `ok=False err=接口调用超时（超过 60 秒未返回）`，随后备源接管，整体 61.6 秒成功。

### D-04 回测页缺少自定义条件直填入口（中）

修复：
- `frontend/src/pages/BacktestPage.tsx` 新增「自定义选股条件（JSON，可选）」文本框，与「选股策略」下拉构成二选一（两者都空会拦下，不发起无效请求），并对 JSON 做即时解析校验。
- `frontend/src/api/client.ts` 的 `backtestApi.run` payload 增加 `strategy_id`（可选）与 `conditions`。

配套纠正：原先示例里的因子 `pct_change` 不在后端可用因子清单内（会被 `ScanSpec` 校验拒绝，导致回测直接失败），已改为可用因子示例 `roe >= 15`。

实测：飞牛回测页出现该入口；用 `{"logic":"and","conditions":[{"factor":"roe","op":">=","value":15}]}` 实跑回测成功。

### D-05 pywencai 问财通道不可用（中）

现象：`research_report` / `stock_select` 主源调用 `pywencai.get` 抛 `AttributeError("'NoneType' object has no attribute 'get'")`。

根因：与 node、pywencai 依赖无关，是问财接口层不可达/改版。

修复：
- `backend/app/collectors/wencai.py` 拆分 `except AttributeError`，抛出与 cookie 无关的明确提示，便于定位。
- 新增备源 `backend/app/collectors/spot_select.py`（`AkshareSpotSelectCollector`，全市场快照本地筛选）。
- `backend/app/services/source_seed.py` 为 `stock_select` 补齐备源登记行。

实测：飞牛数据源清单已含备源（`akshare-全市场快照本地筛选(备用)`），主源失败时可由备源兜底。

### D-06 cron 校验过弱（中）

现象：`report_am_cron = "99 99 * * *"` 之类的非法表达式会被直接保存。

修复：
- `backend/app/services/config_store.py` 的 `_check_cron` 改用 `CronTrigger.from_crontab` 做真实校验。
- `backend/app/scheduler/registry.py` 的 `build_scheduler` 增加双层 try/except，单个任务配置异常时降级而不影响整体调度。

实测：飞牛非法 cron 返回 400（并给出具体错误），合法 cron 返回 200。

### D-07 未知配置项被静默忽略（中）

现象：`POST /api/config/save` 提交 `{"not_a_real_key": 1}` 会返回 200，未知键被悄悄丢弃。

修复：`backend/app/api/config.py` 的请求模型加 `model_config = ConfigDict(extra="forbid")`。

实测：飞牛返回 400，提示 `not_a_real_key Extra inputs are not permitted`。

### D-08 需参数数据源连通性测试必然失败（中）

现象：像日线这类需要入参（如股票代码）的数据源，连通性测试固定失败。

修复：
- `backend/app/services/source_registry.py` 的 `probe_source(db, source_id, params=None)` 会把数据源自带的 `params_template` 与调用方传入参数合并。
- `backend/app/api/datasource.py` 新增 `InterfaceTestIn`，测试端点接受可选 body `{"params": {...}}`。
- `frontend/src/components/DataSourcePanel.tsx` 新增 `sampleParams()`，测试时自动带上示例参数。

实测：飞牛用 kline 的 akshare 备源（`akshare-新浪日线(含复权因子)`），`code=000001` 返回 8468 条、`code=600519` 返回 6036 条（参数透传生效）；不带 body 仍返回 200（向后兼容）。

### D-09 方法不匹配返回 404 而非 405（低）

现象：对仅支持 POST 的接口发 GET，返回 404「接口不存在」，而非 405 且不带 `Allow` 头。

根因：新版 FastAPI 的 `include_router` 不再把子路由平铺进 `app.routes`，而是包装为 `_IncludedRouter`（无 `path` / `methods`），真实路由位于 `original_router.routes`，前缀在 `include_context.prefix`。原实现遍历 `app.routes` 取不到方法集合，于是误判为「路径未注册」。

修复：
- `backend/app/main.py` 改为递归展开路由注册表（新增 `_iter_route_methods`，兼容新旧 FastAPI），并缓存 `_API_METHODS`；`spa_fallback` 对 `/api/*` 返回 405、对确实不存在的路径返回 404。
- `backend/app/core/errors.py` 的 `_envelope` 支持 `headers` 透传，`on_http_error` 传递 `exc.headers`，使 405 真正携带 `Allow`；错误码表补 `405`。

实测：飞牛 `GET /api/auth/login` → **405**，`Allow: GET, OPTIONS, POST`；`DELETE /api/config/get` → 405，`Allow: GET`；不存在的路径仍 404。

### D-10 任务筛选缺少「已跳过」（低）

修复：`frontend/src/pages/TaskPage.tsx` 补充 `skipped` 筛选项与状态标签（后端 `status` 白名单本就包含 `skipped`）。

实测：飞牛任务监控页状态下拉含「运行中 / 成功 / 失败 / 告警 / 已跳过」，选中「已跳过」显示 0 条且无报错。

### D-11 任务详情列暴露原始 SQL 与堆栈（低）

修复：`backend/app/api/task.py` 新增 `summarize_message()`，对任务 `message` 做摘要化（压缩成单行、去除 SQL 语句块与异常堆栈）。

实测：飞牛 50 条任务 message 无 SQL 块、无堆栈、无多行；任务监控页 message 列无泄漏。

### D-12 空数据回测指标口径不一致（低）

现象：区间内无有效交易样本（平仓 0 笔）时，收益类指标仍按 0 展示，容易误读。

修复（**仅展示层**）：`frontend/src/pages/BacktestPage.tsx` 增加 `noSamples = closed_trades === 0`，平仓笔数为 0 时四项收益指标（总收益 / 胜率 / 最大回撤 / 盈亏比）统一显示「—」，并给出「样本不足」提示。后端「空数据回测返回成功」的既有契约保持不变。

实测：飞牛 UI 实跑（`roe >= 15`，当前无 K 线数据）→ 四项指标均为「—」，出现「样本不足：区间内平仓笔数为 0，收益类指标不具参考意义」提示；数据库记录 `status=success`、`closed_trades=0`、`progress.percent=100.0`，与既有契约一致。

### D-13 前后端缩进异常（低）

修复：`frontend/src/api/client.ts` 及 `frontend/src/pages/TaskPage.tsx` 的异常缩进已修正。

### D-14 报告降级未回传失败原因（低）

修复：
- `backend/app/api/report.py` 的响应增加 `fallback_reason`。
- `frontend/src/components/ReportViewer.tsx` 在降级展示时携带原因提示。

实测：飞牛 `regenerate` 返回 `fallback=True`、`fallback_reason=未配置 LLM API Key（请先在系统设置保存）`。
说明：报告降级本身是因为未配置 LLM API Key（配置项问题，非缺陷）；本次修复只是把原因如实回传给前端。

## 四、修复后的部署方式

修复已随源码提交进入本仓库。落地到已有部署实例有两条路：

- **方式 A（省事）：用挂载覆盖运行**——通过 `docker-compose.override.yml` 把修复后的后端源码与前端构建产物的目录挂载进 `dsa-app` 容器，无需重建镜像。注意：若直接替换被挂载的整个目录，必须重启 `dsa-app` 容器，否则挂载点仍指向旧目录。
- **方式 B（持久）：用本仓库源码重建镜像**——`docker build` 生成新镜像标签后替换，然后可删除 override。
