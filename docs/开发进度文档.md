## 一、使用说明（先读这里）

### 1. 执行规则
1. **按任务号顺序执行**（T0.1 → T8.7），一次专注一个任务；标 ★ 的是关键任务，不可跳过或降级交付。
2. **每个任务完成的定义 = 验收标准全部通过**，不是"代码写完"。验收留证据（命令输出/截图/测试结果）在 commit message 或任务备注。
3. **做完一项，立刻更新本文档**：把该任务"状态"从 `⬜ 未开始` 改为 `✅ 完成 2026-XX-XX`；进行中改 `🔄`；延期/阻塞改 `⏸` 并写备注。阶段完成后更新"完成度总览"。
4. **一次 commit 对应一个任务**，message 前缀任务号：`T1.7: K线采集（mootdx主源+断点续采）`。
5. **代码与文档同步**：改动涉及需求/口径/接口变化时，同步更新开发文档并在"更新日志"记一行。
6. 与计划有偏差（换方案、砍范围、工时超 50%）→ 在任务末尾加 `> 备注：` 记录，不要静默偏离。

### 2. 状态图例
`⬜ 未开始` ｜ `🔄 进行中` ｜ `✅ 完成 2026-XX-XX` ｜ `⏸ 暂缓/阻塞（写原因）`

### 3. 接手须知（给程序员 / AI 编码代理）
- **阅读顺序**：开发文档「风险前置声明」→ 开发文档全文 → 本文档「项目速览」→ 从 T0.1 开始。
- **硬约束（违反即返工）**：
  1. 不接实盘、不自动下单、不荐股（开发文档 §风险前置声明）；
  2. 登录鉴权覆盖**全部 API**（白名单仅 `/api/health`、`/api/auth/login`）；
  3. 容器与调度器必须 `TZ=Asia/Shanghai`；
  4. 所有数据接口走 `data_source_config` 配置选路，**禁止硬编码接口**（开发文档 §2.4）；
  5. LLM API Key 只经 `.env` 注入，不入库、不回显、不进 git；
  6. 回测口径四件套：复权、含退市股、涨跌停撮合、滑点（开发文档 §4 模块5）。
- **AI 代理特别提示**：外部免费数据接口失效是常态——遇到 403/改版/超时，优先在接口配置登记新线路（或降级），不要改死代码绕过配置层；拿不准的口径问题先查开发文档，仍不明确就在备注里提问而不是猜。
- **技术栈已定，不要随意更换**（开发文档 §2.2）：Python 3.11 + FastAPI + SQLAlchemy2/Alembic + APScheduler + MySQL8；React18 + Vite + TS + Arco/AntD + ECharts；指标 TA-Lib（pandas 降级）；LLM LiteLLM。`requirements.txt` 锁版本（`pywencai==0.12.2` 等）。
