## 风险前置声明（重要）

本系统定位为**个人投研辅助工具**，只负责数据的搜集、整理、分析与报告生成，**不代替使用者做出买卖决策**；不荐股、不带单、不接入实盘交易、不自动下单。系统中输出的所有报告、选股结果、回测结论均**不构成投资建议**。

## 1. 项目概述

### 1.1 项目背景
个人投资者做投研时，手动收集行情、财务、新闻、研报、复盘等工作量大、耗时且容易遗漏。本系统通过**自动化的数据归集 + AI 报告生成**，把"收料"和"干活"两大环节交给系统完成，让使用者把精力放在**最终判断**上。

### 1.2 产品形态
- **B/S 网页架构**，单页仪表盘（Dashboard）风格，深色金融主题
- 前端：网页（可视化图表、Markdown 报告渲染）
- 后端：Python
- 部署：Docker 容器化（兼容飞牛 / 宝塔环境）
- 浏览器直接访问，PC 优先，平板适配
- **访问控制**：登录后方可使用（单用户账号体系，详见 3.4）

### 1.3 核心目标
1. 全市场数据自动归集与清洗入库
2. **多数据源交叉互备**：全免费开源数据源，主备自动切换、交叉对账，稳定不中断
3. **数据源接口可配置**：所有数据接口登记在接口配置表中，可在系统设置页增删改、启停、调优先级、测连通性——默认接口失效时可自行更换，不用改代码（详见 2.4）
4. 自动计算财务指标与技术指标
5. 定时生成 AI 盘前早报、盘后复盘报告
6. 支持自定义选股条件 + 历史回测验证
7. 热点题材库、资讯过滤、掘金观察池
8. 底层基座可扩展（选股策略、数据分析、量化）

### 1.4 非功能目标
- 不接入实盘、不自动下单（硬约束）
- 数据采集、回测等重任务后台异步执行，不阻塞前端
- 任务失败自动重试、全链路日志留存
- 数据本地持久化，减少对数据源的重复请求
- 登录鉴权覆盖全部 API；全站 HTTPS（生产环境）；定时任务统一使用 Asia/Shanghai 时区

## 2. 系统架构设计

### 2.1 架构分层

```

│  前端 Web（SPA 仪表盘 / 图表 / Markdown 报告）  │

                    │ HTTP API（统一鉴权）
┌───────────────────▼─────────────────────────┐
│              后端服务层（Python）               │
│   ┌───────────┬───────────┬───────────────┐  │
│   │ 任务调度    │ 业务接口    │ LLM 报告引擎    │  │
│   └─────┬─────┴─────┬─────┴───────┬───────┘  │
└─────────┼───────────┼─────────────┼──────────┘
          ▼           ▼             ▼
┌─────────────────────────────────────────────┐
│ 数据采集器 │ 指标计算引擎 │ 选股/回测引擎 │ 热点/资讯 │
│        （采集器按接口配置表选路，主备自动切换）      │
└───────────────────┬─────────────────────────┘
                    ▼
┌─────────────────────────────────────────────┐
│    数据存储（MySQL + 文件缓存；Redis 可选）        │
└─────────────────────────────────────────────┘
```

### 2.2 技术栈选型建议
| 层次 | 选型 | 说明 |
|---|---|---|
| 前端 | React + Vite + Ant Design / Arco + ECharts | 深色仪表盘、K线、资金图、净值曲线 |
| 后端 | Python + FastAPI | 异步、性能好、生态丰富 |
| 定时调度 | APScheduler | cron 表达式，**时区固定 Asia/Shanghai**，交易日内触发 |
| 数据库 | MySQL 8 | 业务数据、报告、策略（容器内运行，不映射宿主端口） |
| 缓存/队列 | Redis（**可选，一期不启用**） | 单机进程内调度 + MySQL 任务表即可；二期多实例再启用 |
| LLM 对接 | LiteLLM / OpenAI SDK 封装 | 统一接入多家 API（通义千问、Kimi、Mimo 等），支持切换模型 |
| 数据源 | 多源免费交叉互备（详见第 3 章） | 通达信/新浪/问财/腾讯/东方财富，全免费，主备切换+交叉对账 |
| **运行时补充** | **Node.js ≥ 18** | `pywencai` 依赖 Node.js，镜像内必须安装，否则问财线不可用 |
| 部署 | Docker Compose + GitHub Actions 出镜像 | 单镜像交付，兼容飞牛/宝塔（详见第 8 章） |

> 依赖版本策略：`requirements.txt` 锁定关键包版本（如 `pywencai==0.12.2`、`mootdx`、`easyquotation`、`akshare`），升级前先在开发环境验证接口可用性。

### 2.3 数据源架构与交叉互备方案（依据视频2实测）

**设计目标**：搭建全免费、交叉互备的投研数据系统，任何单点数据源失效时自动切换备用线路，不同来源数据可交叉对账，保障长期稳定运行（实测方案已稳定运行半年无中断）。

#### 2.3.1 数据源实测结论（7 款 → 保留 5 款免费源）

| 数据需求类型 | 主数据源 | 说明 |
|---|---|---|
| 实时 / 历史 K 线 | 通达信 `mootdx` | 免费，K线主源 |
| 全市场快照 / 自选股 | 新浪 `easyquotation` | 免费，实时快照 |
| 复杂条件筛选 / 研报 | 同花顺问财 `pywencai` | 免费，条件选股与研报（风险见 2.3.3） |
| 备用实时 / K 线 | 腾讯接口（`akshare` 封装） | 免费，K线/实时备用 |
| 备用实时 / K 线 | 东方财富（`akshare` 封装） | 免费，K线/实时备用 |

> 淘汰项：**TuShare**（核心数据需攒积分、积分墙限制）、**Ashare**（无人维护、接口全挂）。  
> 命名澄清：文档早期写的"腾讯 stock-api"含义模糊，**统一改为 `akshare` 提供的腾讯/东财接口**，减少第三方依赖数量。

#### 2.3.3 避坑经验（视频2强调 + 实测补充）

1. **TuShare 积分墙限制**：核心数据接口需积分门槛，不适合作为免费基座主源。
2. **无维护项目接口易失效**：无人维护的开源数据源（如 Ashare）随时可能接口全挂，务必选择活跃维护的项目。
3. **东方财富禁止批量调用**：高频批量请求会触发风控并被拉黑，仅作备用线路、控制频率使用（各接口 QPS 上限见 2.4 接口清单）。
4. **pywencai（问财）不稳定的应对**（重要）：
   - cookie 会过期导致 403——需要维护 cookie 更新流程（手动更新或登录态刷新），失效时告警；
   - 问财网页改版会导致解析失效——**锁定版本**（如 `pywencai==0.12.2`），升级前验证；
   - **依赖 Node.js ≥ 18**——Docker 镜像内必须安装；
   - 失败降级：pywencai 不可用时，条件选股走本地指标缓存兜底，研报切换东财备用源，绝不阻塞主流程。
5. **研报不能单点**：研报/研报摘要除问财外，增加东财研报接口（`akshare`）作备用，符合"多源互备"原则。

#### 2.3.4 八大模块与互备机制
- AI 将采集数据整理为**八大模块**，每个子项均配置**备用数据源**，可**自动切换线路**。
- 同一数据的多个来源可**交叉对账**，数据不一致时以对账结果为准（对账规则：多源取多数一致值；两源不一致时以主源为准并记录差异到 `data_reconcile`），保障准确性。
- 相关数据明细总表另附（视频评论区挂出）。

### 2.4 数据源接口可配置化（核心设计，必做）

**设计目标**：任何默认接口失效时，用户可在**系统设置页直接更换/新增接口**，无需改代码重新发版。

#### 2.4.1 接口配置模型（`data_source_config` 表）

| 字段 | 说明 |
|---|---|
| 数据类型 | K线 / 快照 / 财务 / 资金流向 / 条件选股 / 研报 / 资讯 / 热点 / 涨停情绪 / 交易日历 |
| 接口名称 | 展示名，如"通达信 mootdx 日线" |
| 实现方式 | Python 函数（包名.函数名）或 HTTP 接口（URL + 参数模板） |
| 参数模板 | 代码/日期等占位参数 |
| 角色/优先级 | 主源(1) / 备用(2,3...)，数字越小优先级越高 |
| QPS 上限 / 超时秒数 | 限流保护，防止触发数据源风控 |
| 启用状态 | 启用 / 停用（停用不参与选路） |
| 健康状态/最近错误 | 连通性测试结果、最近一次失败原因（只读） |

#### 2.4.2 采集器调用约定
1. 采集器**不硬编码任何接口**，统一按 `数据类型 → 启用且优先级最高` 取接口；
2. 失败/超时自动降级到下一优先级，全部失败则记 `task_log` 并告警；
3. 每次调用写 `data_source_log`（接口、耗时、状态），支撑"数据源健康"页展示；
4. 系统设置页提供**连通性测试**按钮（单接口试采集 1 条）。

#### 2.4.3 接口注册清单（初始登记，均可在设置页修改/新增）

| 数据类型 | 初始主源 | 初始备用 | QPS 建议 |
|---|---|---|---|
| 日线 K 线 | mootdx（通达信） | akshare-腾讯、akshare-东财 | 主 2 / 备 1 |
| 全市场快照 | easyquotation（新浪） | akshare-东财 | 1 |
| 财务数据 | akshare-东财 | akshare-新浪 | 1 |
| 资金流向 | akshare-东财 | akshare-同花顺 | 1 |
| 条件选股 | pywencai（问财） | 本地指标缓存兜底 | 0.5 |
| 研报 | pywencai | akshare-东财研报 | 0.5 |
| 财经资讯 | akshare-财联社电报 | 同花顺快讯 / RSS | 0.5 |
| 热点/概念板块 | akshare-东财概念 | pywencai | 0.5 |
| 涨停/情绪统计 | akshare-东财涨跌停 | 计算兜底（基于快照） | 1 |
| 交易日历 | akshare-交易日历 | 本地缓存年更 | 0.2 |

## 3. 功能清单（严格对齐视频1演示）

系统划分为**收料模块（数据）**和**干活模块（输出）**两大块。

### 3.1 收料模块 · 自动数据采集与预处理
| 功能 | 说明 |
|---|---|
| 全市场数据归集 | 覆盖 A 股 5000+ 个股、90+ 行业、377 个概念板块 |
| 历史数据存储 | 20 年 K 线、10 年财务数据 |
| 每日自动抓取 | 多数据源抓取行情、板块、资金流向、财经新闻、市场热点、研报，全程约 5 分钟 |
| 自动计算财务指标 | 基于三大财务报表自动算出 30 项指标（ROE、毛利率、现金流等） |
| 自动计算技术指标 | 16 项指标（均线、MACD 等），随查随出 |
| 自定义选股 | 输入个人选股条件，约 20 秒扫描全市场 |
| 历史回测 | 调用 20 年历史数据，回测验证选股策略有效性 |

### 3.2 干活模块 · 自动产出投研报告
| 功能 | 说明 |
|---|---|
| 盘前投资早报 | 交易日早 8:00 自动生成，约 2000 字，**7 个维度**（见下） |
| 盘后自动复盘 | 交易日 17:00 生成：市场情绪打分、涨停数量、涨停梯队、主线板块、资金流向、风险预警、次日观察计划，并自动验证策略成功率 |
| 热点题材库 | 自动收集每日市场热点，按产业链结构化整理归档 |
| 掘金模块 | 直接设置重点关注的概念/主题，方便查看 |
| 资讯过滤 | 全天候抓取财经资讯（具体源见 2.4.3），过滤噪音，只保留对盘面有影响的消息 |

**盘前早报 7 个维度（补齐口径）**：
1. 速读摘要
2. 隔夜市场大事（美股/港股/商品/汇率）
3. 市场情绪预判
4. 资金动向（主力资金净流入；北向仅披露成交额口径，净流入为季度披露不可实时取）
5. 操作提醒 / 风险提示
6. 今日观察方向（主线板块、题材线索）
7. 今日重要事件与数据日历（新股申购、解禁、经济数据、财报日程）

### 3.3 底层基座
1. 底层整合个股、板块、K线、资金、财务、研报、新闻、基金等全套基础数据。
2. 基座搭建完成后，可继续扩展开发：选股策略、数据分析、量化相关功能。

### 3.4 用户登录与访问控制（一期必做）
- 登录后方可访问工作台；**后端统一鉴权中间件覆盖全部 API**（含配置、触发采集等写接口）
- 账号：单管理员账号（用户名 + 密码哈希存储），支持修改密码；不做注册/多用户（二期规划）
- 登录接口限速：连续失败 5 次锁定 10 分钟（防暴力破解）
- 会话：登录签发 token（HttpOnly Cookie 或 Bearer），有效期 7 天，可主动退出
- 生产环境全站 HTTPS（宝塔 SSL / 飞牛反代），密码不明文过网

## 4. 后端模块详细设计

### 模块 1：数据采集器（多源交叉互备）
- **采集范围**：全市场个股、行业、概念板块
- **数据类型**：日线 K 线（20年）、财务报表（10年）、资金流向、涨停数据、财经新闻、研报
- **多源分工**：按数据类型分流到免费源（通达信/新浪/问财/腾讯/东方财富），各子项配置备用源；**具体接口来自 2.4 接口配置表，不硬编码**
- **自动切换**：主源采集失败或超时，自动切换备用线路
- **交叉对账**：同一数据多来源交叉比对，不一致时以对账结果为准
- **调度**：交易日定时自动采集（时间线见 4.9）；支持手动触发
- **清洗**：去重、异常值过滤、停牌标记、数据对齐
- **输出**：标准化后入库，供指标计算使用

### 模块 2：指标计算引擎
- **财务指标（30项）**：ROE、毛利率、净利率、资产负债率、经营现金流等，由财报自动计算（**报告期粒度**）
- **技术指标（16项）**：MA、MACD、KDJ、RSI、BOLL 等（**交易日粒度**）
- 存储分离：财务指标、技术指标分表存储（见第 6 章）
- **增量更新**：每日只更新当日新增数据，历史指标缓存，避免重复计算
- **对外接口**：单标的指标查询、全市场指标筛选

### 模块 3：AI 报告生成引擎（核心）
两套定时报告模板（完整维度见 3.2）：

**盘前早报（交易日 08:00）**，约 2000 字，7 个维度：速读摘要、隔夜市场大事、市场情绪预判、资金动向、操作提醒/风险提示、今日观察方向、今日重要事件日历。

**盘后复盘（交易日 17:00）**：
- 市场情绪打分（计算口径固定为规则化打分，保证可复现；规则文档随模板发布）
- 涨停数量与涨停梯队
- 主线板块
- 资金流向
- 风险预警
- 次日观察计划
- 策略成功率自动验证

**机制**：结构化数据 + 固定 Prompt → LLM 生成 Markdown 报告 → 写入数据库 → 前端直接渲染。支持手动重新生成单日报告。

### 模块 4：选股模块
- 组合条件：财务因子 + 技术因子
- 策略命名保存，后续可复用
- 全市场扫描，约 20 秒输出候选池
- 结果展示：标的列表、匹配条件高亮、指标预览
- 因子范围约束：模式 B 下选股因子以指标缓存覆盖的指标清单为准（见 5.3），缺因子时实时计算兜底

### 模块 5：回测引擎
- **输入**：选股策略、起止时间、初始资金、交易规则（T+1、手续费、涨跌停限制）
- **输出**：累计收益曲线、胜率、盈亏比、最大回撤、每笔模拟交易记录
- **回测数据口径（必守，否则结果虚高）**：
  1. **复权**：K 线存不复权价 + 复权因子（`adj_factor`），回测统一按后复权计算，展示转前复权
  2. **幸存者偏差**：股票池含**已退市股票**，历史回测不得剔除
  3. **撮合规则**：涨停不买入、跌停不卖出；停牌日跳过；信号次日开盘价成交（T+1）
  4. **滑点**：默认单边 0.1% 可配置
- **说明**：仅历史数据模拟，回测结果可视化展示，页面强制展示风险提示
- **异步**：长周期回测放入任务队列，防止请求超时

### 模块 6：热点题材库 & 资讯过滤
- 自动抓取每日热点，按产业链标签结构化归档
- 资讯降噪：LLM 过滤无关新闻，只保留对盘面有影响的消息，标记高/中/低影响等级
- 检索：支持按板块、关键词、日期检索
- 资讯源清单及频率限制见 2.4.3（东财类接口严格限流，作备用/低频使用）

### 模块 7：掘金观察池（自选）
- 用户添加重点关注标的，快速查看快照
- 联动：选股结果、热点、复盘中的标的一键加入观察池
- 支持按概念/主题维度配置关注
- 一期单用户，`watch_list` 不做多用户隔离

### 模块 8：任务调度 & 系统配置
- 定时任务开关、采集时间配置（早报 08:00、复盘 17:00 可配置）
- LLM 多模型配置；**API Key 由 `.env` 环境变量注入**，配置页只做遮蔽显示（尾号 4 位）+ 连通性测试，不入库、不回显明文
- **数据源接口配置管理**：对接 2.4——接口的增删改、启停、优先级调整、连通性测试
- **账号管理**：修改登录密码
- **技术指标入库开关**：开启→指标写库并每日增量；关闭→走本地缓存方案（默认）
- 指标缓存保留天数、指标计算引擎（TA-Lib / pandas）配置
- 任务日志、失败告警、手动触发入口

### 4.9 调度时间线（cron 总表，时区 Asia/Shanghai）

| 时间 | 任务 | 说明 |
|---|---|---|
| 每日 07:30（交易日） | 隔夜资讯/外围市场采集 | 为 08:00 早报供料 |
| 交易日 08:00 | 生成盘前早报 | 7 维度模板 |
| 交易日 15:30 | 收盘数据采集（行情/资金/涨停） | 收盘后数据源稳定 |
| 交易日 16:00 | 指标批量计算 → 写指标缓存 | 模式 B |
| 交易日 17:00 | 生成盘后复盘 | 含策略成功率验证 |
| 每小时（09:00-15:00 交易时段） | 资讯增量抓取 | 严格限流 |
| 每周日 20:00 | 数据对账 + 备份 + 数据源健康巡检 | `data_reconcile` 记录 |

> **所有调度前置判断交易日**（`trade_calendar` 表，来源见 2.4.3）：非交易日只跑资讯线和巡检，不生成报告。容器与调度器必须使用 `TZ=Asia/Shanghai`。

## 5. 数据存储方案（入库 vs 不入库）

> 针对"技术指标是否入库"提供两种可切换模式，前端系统配置页提供开关（默认推荐：不入库）。两种模式功能完全一致，仅影响存储占用、查询速度与计算时机。

### 5.1 两种模式对比

| 维度 | 模式A：技术指标入库 | 模式B：技术指标不入库（推荐） |
|---|---|---|
| 存储占用 | 高（20年全A约 +10GB） | 低（仅原始K线 + 指标缓存，几乎无额外占用） |
| 选股响应 | 最快（直接查表） | 毫秒级（读本地指标缓存） |
| 指标时效 | 需每日增量更新库表 | 收盘后批量计算写缓存，按交易日滚动保留 |
| 回测性能 | 快（查库） | 加载原始K线实时计算 |
| 维护成本 | 需维护指标表、索引、增量 | 低，缓存每日滚动覆盖 |
| 适用 | 指标查询极其频繁、追求极致速度 | 本项目默认（存储友好、够快） |

### 5.2 数据归属（什么入库、什么可缓存）

| 数据类型 | 是否入库 | 说明 |
|---|---|---|
| 日线 K 线（20年，不复权价+复权因子） | **必须入库** | 回测、指标计算的数据底座 |
| 财务数据（10年） | **必须入库** | 财务选股因子来源 |
| 个股/行业/题材标签 | **必须入库** | 基础元数据 |
| 涨停/情绪/资金统计 | **必须入库** | 复盘、情绪分析依赖 |
| 早报/复盘/资讯/日志 | **必须入库** | 报告与审计记录 |
| 交易日历 | **必须入库** | 调度判断依据 |
| 数据源接口配置 | **必须入库** | 2.4，设置页可改 |
| 技术指标 | **可开关** | 入库 or 缓存，由设置页开关控制 |

### 5.3 技术指标缓存机制（模式B核心）

```
每日收盘采集完成
       │
       ▼
后台任务加载当日全市场 K 线
       │
       ▼
批量计算全市场技术指标（TA-Lib，pandas 降级）
       │
       ▼
写入本地指标缓存文件（Parquet，按交易日一版）
       │
       ▼
按交易日滚动保留 N 天（默认 3 天），过期版本清理
```

- 缓存**按交易日滚动保留 N 天（默认 3）**：覆盖周末/节假日与单日采集失败的空窗；不长期累积占用
- 选股时优先读取本地指标缓存做筛选，**全程不访问外网数据源**，无接口风控、毫秒级响应
- **因子覆盖约束**：缓存内含 16 项技术指标的固定参数版本；策略用到缓存外的自定义参数（如 MA10>MA60）时，实时计算兜底并提示
- **失效兜底**：缓存缺失/过期时，选股回退到实时计算（慢但正确），并在任务日志告警
- 回测时不依赖缓存，直接加载原始 K 线实时计算

### 5.4 设置项设计（系统配置页）

| 配置项 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| 技术指标入库开关 | 布尔开关 | 关闭（不入库） | 开启→指标写入库表并每日增量；关闭→走本地缓存方案 |
| 指标缓存保留天数 | 数字 | 3 | 按交易日滚动保留 N 个版本，过期自动清理 |
| 指标计算引擎 | 下拉 | TA-Lib | TA-Lib / pandas 内置实现（降级用） |
| 数据源接口配置 | 增删改表 | 见 2.4.3 | 接口的新增/修改/启停/优先级/连通测试 |
| 早报/复盘定时时间 | 时间 | 08:00 / 17:00 | cron 可配置 |
| LLM 模型选择 | 下拉 | 通义千问 | 多模型切换 |
| LLM API Key | 密码框（遮蔽） | — | 仅环境变量注入，页面只显示尾号+测试按钮 |
| 登录密码管理 | 修改密码 | — | 单管理员账号 |

### 5.5 容量估算（全 A 约 5300 只）

| 方案 | 20年全量估算 | 年增量 | 说明 |
|---|---|---|---|
| 模式A（指标入库，MySQL） | 约 24GB | 约 1.2GB/年 | K线+指标全在 MySQL |
| 模式B（指标不入库，MySQL基础数据） | 约 6~7GB | 约 200MB/年 | **K线/财务仍入 MySQL**；Parquet 仅作指标缓存格式（单交易日×N天，MB级） |

> 口径澄清：早期"模式B + Parquet 1.5~2GB"指极端情况下 K 线改存 Parquet 文件层的可选优化（二期），一期 K 线一律入 MySQL，Parquet 只用于指标缓存。  
> 注："20 年"为尽力回填——上市不足 20 年的按实际上市日；入库时校验每只标的实际起始日期。

## 8. 部署方案

> 详细分步操作见 `docs/部署指南-飞牛与宝塔.md`；配套文件：根目录 `docker-compose.yml`、`.env.example`、`.github/workflows/build-image.yml`。

### 8.1 镜像构建与交付（GitHub Actions）
- **单镜像交付**：后端（FastAPI）托管前端构建产物，镜像内含全部运行依赖（**TA-Lib C 库、Node.js ≥ 18**）
- 构建：GitHub Actions（打 tag `v*` 或手动触发），产出：
  1. GHCR 镜像 `ghcr.io/yueyoue/daily-stock-ai:<版本>`
  2. 离线包 `daily-stock-ai-image.tar.gz`（`docker save`，供弱网环境导入）
- 取镜像三通道：**离线 tar 导入（推荐）＞ 阿里云 ACR（国内快）＞ GHCR 直连（备选）**。原因：ghcr.io 国内拉取极慢/超时是常态。

### 8.2 运行拓扑（Docker Compose）
- `app`（后端+前端，唯一对外端口 8000）+ `mysql`（**不映射宿主端口**，内部网络连接）；`redis` 可选（一期不启用）
- **全部服务设置 `TZ=Asia/Shanghai`**（定时报告 08:00/17:00 依赖，缺了必错点）
- 数据卷：`mysql_data`（K线/财务/报告）+ `./data`（指标缓存、导出文件）
- `restart: unless-stopped`；健康检查 `/api/health`；容器日志轮转（50m×3）

### 8.3 平台要点
- **飞牛 fnOS**：Docker 导入镜像（或配镜像加速器拉取）→ Compose 项目启动；部署目录 `/vol1/docker/daily-stock-ai/`（文件管理可见，便于备份）
- **宝塔**：Docker 管理器跑 Compose + **nginx 反代 + SSL 证书**（对外只开 80/443）；⚠️ 宝塔自带 MySQL 占 3306，容器 mysql 不映射宿主端口即无冲突（需外部连库调试时临时映射 `3307:3306`）

### 8.4 安全
- 登录鉴权覆盖全部 API（3.4）：登录口令 + 会话 + 登录限速 + 会话过期
- 生产环境 HTTPS（宝塔 SSL）；反代 Basic Auth 可作额外兜底
- LLM API Key 仅经 `.env` 环境变量注入，不入库、不回显前端
- `.env` 加入 `.gitignore`，不进镜像层（构建参数与运行时环境变量分离）

### 8.5 备份与恢复
- 每日 `mysqldump`（飞牛计划任务 / 宝塔计划任务）：`docker exec dsa-mysql mysqldump -udsa -p"$DB_PASSWORD" daily_stock_ai | gzip > dsa_$(date +%F).sql.gz`，保留 7 天
- 升级前手动备份一次；NAS 目录快照作第二保险
- 恢复演练：部署验收时实际演练一次导入

### 8.6 升级
- 离线通道：下载新 tar → 导入镜像 → `docker compose up -d`
- 在线通道：`docker compose pull && docker compose up -d`
- 表结构变更（破坏性）先看 release note + 先备份

## 10. 风险与限制

1. **数据源稳定性**：免费开源接口随时可能失效或被风控。应对：多源主备切换 + 交叉对账；避开东方财富批量调用；仅选用活跃维护的项目；**接口可配置化（2.4）保证失效可随时换源**。
2. **pywencai（问财）脆弱**：cookie 过期、网页改版解析失效、依赖 Node.js。应对：锁版本、cookie 维护流程、失败降级（本地缓存/东财研报）、告警。
3. **数据源频率限制**：免费接口有调用频率上限，需做好缓存、限流与退避重试（QPS 上限登记在接口配置表）。
4. **LLM 输出不稳定**：Prompt 需持续调优，报告强制结构化，关键数值需校验。
5. **回测不等于未来**：历史回测结果不能代表未来收益，页面需强制展示风险提示；回测口径（复权、退市股、撮合）严格执行 4 模块 5。
6. **行情粒度**：以日线级别投研为主，不做实时高频行情。
7. **北向资金口径**：2024-08 起净流入为季度披露，日度只有成交额——界面与报告不得展示"当日北向净流入"，改用主力资金口径（东财）。
8. **登录安全**：无 HTTPS 的情况下口令可被嗅探——生产必须上 HTTPS；登录限速防暴力破解。
