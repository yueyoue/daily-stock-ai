# 部署指南 — 飞牛 fnOS / 宝塔面板（Docker Compose）

配套文件（放仓库根目录 / 部署目录）：
- `docker-compose.yml`、`.env.example`
- 自包含一键版 compose：见 [README「安装教程 → 方式 A」](../README.md)（内联全部配置与密钥，无需额外建 `.env`）
- `.github/workflows/build-image.yml`（Actions 构建模板）
- 本轮缺陷修复说明：`docs/缺陷修复记录-2026-11-05.md`

## 0. 镜像交付链路（总览）

```
打 tag(v*) 或手动触发 GitHub Actions
        │
        ├─→ 推送 GHCR 镜像（ghcr.io/yueyoue/daily-stock-ai:latest）
        └─→ 产出离线包 daily-stock-ai-image.tar.gz（artifact，保留7天）
                    │
   路线A(推荐)：下载 tar → 飞牛/宝塔"导入镜像" → compose up   ← 最稳，即"拉编译好的镜像到本地"
   路线B：fnOS 配镜像加速器后 docker pull ghcr.io/...          ← ghcr 国内不稳，备选
   路线C(可选)：Actions 同时推阿里云 ACR → docker pull          ← 国内快，需开 ACR 个人版
```

## 1. 飞牛 fnOS

### 路线 0：一键粘贴自包含 compose（新手推荐，无需 `.env`）

飞牛面板「Docker」→「Compose」→「新增项目」，来源选「创建 docker-compose.yaml」，把 [README「安装教程 → 方式 A」](../README.md) 里的自包含 yml **整段**粘贴进去（已内联全部配置与密钥，不用额外建 `.env`），勾选「创建项目后立即启动」。

- 首次启动需 2~4 分钟（MySQL 第一次初始化较慢），期间页面打不开属正常。
- 启动后共 3 个容器：`dsa-app`（应用）、`dsa-mysql`（数据库，不映射宿主端口）、`dsa-init-data`（一次性权限修复容器，跑完 `Exited (0)` 属正常，**别删别重启**——这也是面板显示「部分运行」的原因）。
- ⚠️ 数据库密码只在数据卷首次初始化时生效，之后改 compose 里的密码不会生效反而导致连不上；要改密码或彻底重装需先 `docker compose down -v`（会清空数据库，不可逆）。

### 路线 A：离线导入（推荐）
1. GitHub 仓库 → **Actions → build-image → 最新一次运行 → Artifacts** → 下载 `daily-stock-ai-image`
2. 飞牛 **Docker → 镜像 → 导入**，选中解压出的 `daily-stock-ai-image.tar.gz`（自动 `docker load`）
3. 准备部署目录（建议 `/vol1/docker/daily-stock-ai/`）：
   - 上传 `docker-compose.yml`
   - `cp .env.example .env` 并填写 SECRET_KEY、DB 密码、LLM API Key（生产保持 `API_DOCS_ENABLED=false`）
   - 建 `data/` 子目录（app 数据：Parquet 缓存、导出文件）
4. **Docker → 项目（Compose）→ 创建项目** → 选该目录 → 启动
5. 浏览器访问 `http://飞牛IP:8000`

### 路线 B：在线拉取
1. **Docker → 设置 → 镜像加速器**（fnOS 内置轩辕加速 / 自定义 registry-mirror）
2. **镜像 → 拉取**：`ghcr.io/yueyoue/daily-stock-ai:latest`
3. 拉不动就走路线 A（ghcr 超时是常态，不要硬磕）

### 飞牛注意事项
- **时区**：compose 已带 `TZ=Asia/Shanghai`，勿删——早报 08:00 / 复盘 17:00 全靠它
- **存储**：整个部署目录放 `/vol1/docker/...`，文件管理可见；mysql 默认命名卷，想直观备份可改 bind 挂载（compose 里有注释示例）
- **资源**：内存 ≤8G 的机器，保持 compose 里 `innodb-buffer-pool-size=256M`
- **一次性容器**：`dsa-init-data` 只做数据目录权限修复（`chown -R 1000:1000 /app/data`），执行完即 `Exited (0)`，属正常状态，不要删除或重启
- **备份**：飞牛"计划任务"每日跑 mysqldump（见第 4 节），或开启目录快照

## 2. 宝塔面板

推荐形态：**Docker 起服务 + 宝塔 nginx 反代 + SSL**（对外只开 80/443）。

1. 宝塔软件商店安装 **Docker 管理器** 插件
2. 导入镜像（同飞牛路线 A）或配置镜像加速后拉取
3. 准备目录（如 `/www/docker/daily-stock-ai/`），上传 `docker-compose.yml`，建 `.env`
4. Docker 管理器 → **Compose 项目** → 创建并启动
5. 宝塔**网站** → 添加站点（反向代理）→ `http://127.0.0.1:8000` → 配 SSL 证书
6. 建议给站点开 **Basic Auth**（在无应用层口令前的鉴权兜底，见审查报告 P0-4）

### ⚠️ 宝塔注意事项
- **端口冲突**：宝塔自带 MySQL 占 3306——compose 里的 mysql **不要映射宿主端口**（模板已不映射）
- **防火墙**：反代形态只开 80/443；若直连调试再放行 8000
- 用宝塔 MySQL 替代容器 MySQL 也可以，但要自己建库（utf8mb4）并改 `DATABASE_URL`，个人不建议——多一层耦合

## 3. 首次启动与验证

```bash
cd <部署目录>
cp .env.example .env && vi .env     # 必填 SECRET_KEY / DB_ROOT_PASSWORD / DB_PASSWORD；LLM_API_KEY 建议填
docker compose up -d
docker compose ps                    # 全部 healthy（dsa-init-data 显示 Exited 属正常）
curl http://localhost:8000/api/health
```

- 首次全量采集（20 年 K 线 + 10 年财务）：网页右上角"手动触发采集"，首轮耗时较长，在"任务监控"页看进度
- 时区自检：`docker exec dsa-app date` 应显示 CST（+08），不是 UTC

## 4. 备份

```bash
# 每日 mysqldump（飞牛计划任务 / 宝塔计划任务，保留 7 天）
docker exec dsa-mysql mysqldump -udsa -p"$DB_PASSWORD" daily_stock_ai \
  | gzip > /vol1/backup/dsa_$(date +%F).sql.gz
```
- `data/` 目录（指标缓存、导出文件）可不备份，缓存可重建
- 升级前手动备份一次

### 恢复演练（T8.4 执行）

> 只备份不验证等于没备份。部署验收时**实际跑一次**恢复流程（导到新库校验，不动原库），确认备份可用。

```bash
# 1) 导出（容器内 mysqldump → 落 NAS 目录）
docker exec dsa-mysql mysqldump -udsa -p"$DB_PASSWORD" \
  --single-transaction --default-character-set=utf8mb4 daily_stock_ai \
  | gzip > /vol1/backup/dsa_$(date +%F).sql.gz

# 2) 建新库并导入（验证恢复可行性；只有确认原库损坏、要回滚时才覆盖原库）
gunzip -c /vol1/backup/dsa_$(date +%F).sql.gz > /tmp/restore.sql
docker exec -i dsa-mysql mysql -uroot -p"$DB_ROOT_PASSWORD" \
  -e "CREATE DATABASE dsa_restore CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
docker exec -i dsa-mysql mysql -uroot -p"$DB_ROOT_PASSWORD" dsa_restore < /tmp/restore.sql

# 3) 校验：关键表行数与原库一致 + 迁移版本号一致
docker exec dsa-mysql mysql -uroot -p"$DB_ROOT_PASSWORD" -N -e "
SELECT 'stock_kline',     COUNT(*) FROM dsa_restore.stock_kline
UNION ALL SELECT 'stock_info',       COUNT(*) FROM dsa_restore.stock_info
UNION ALL SELECT 'market_daily',     COUNT(*) FROM dsa_restore.market_daily
UNION ALL SELECT 'stock_finance',    COUNT(*) FROM dsa_restore.stock_finance
UNION ALL SELECT 'report',           COUNT(*) FROM dsa_restore.report
UNION ALL SELECT 'news',             COUNT(*) FROM dsa_restore.news
UNION ALL SELECT 'alembic_version',  COUNT(*) FROM dsa_restore.alembic_version;"
```

**校验口径**：恢复库与原库上述关键表行数一致、`alembic_version` 版本号一致 → 服务能登录 → 报告列表能打开既有报告，即视为恢复成功。

> 演练结论（行数对比、耗时、遇到的问题）：**待 T8.4 实机执行后回填**。
