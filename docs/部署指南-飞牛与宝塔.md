# 部署指南 — 飞牛 fnOS / 宝塔面板（Docker Compose）

配套文件（放仓库根目录 / 部署目录）：
- `docker-compose.yml`、`.env.example`
- `.github/workflows/build-image.yml`（Actions 构建模板）

---

## 0. 镜像交付链路（总览）

```
打 tag(v*) 或手动触发 GitHub Actions
        │
        ├─→ 推送 GHCR 镜像（ghcr.io/yueyoue/daily-stock-ai:latest）
        └─→ 产出离线包 daily-stock-ai-image.tar.gz（artifact，保留7天）
                    │
   路线A(推荐)：下载 tar → 飞牛/宝塔"导入镜像" → compose up   ← 最稳，即"拉编译好的镜像到本地"
   路线B：fnOS 配镜像加速器后 docker pull ghcr.io/...          ← ghcr 国内不稳，备选
   路线C(可选)：Actions 同时推阿里云 ACR → docker pull          ← 国内快，需开 ACR 个人版
```

---

## 1. 飞牛 fnOS

### 路线 A：离线导入（推荐）
1. GitHub 仓库 → **Actions → build-image → 最新一次运行 → Artifacts** → 下载 `daily-stock-ai-image`
2. 飞牛 **Docker → 镜像 → 导入**，选中解压出的 `daily-stock-ai-image.tar.gz`（自动 `docker load`）
3. 准备部署目录（建议 `/vol1/docker/daily-stock-ai/`）：
   - 上传 `docker-compose.yml`
   - `cp .env.example .env` 并填写 DB 密码、LLM API Key
   - 建 `data/` 子目录（app 数据：Parquet 缓存、导出文件）
4. **Docker → 项目（Compose）→ 创建项目** → 选该目录 → 启动
5. 浏览器访问 `http://飞牛IP:8000`

### 路线 B：在线拉取
1. **Docker → 设置 → 镜像加速器**（fnOS 内置轩辕加速 / 自定义 registry-mirror）
2. **镜像 → 拉取**：`ghcr.io/yueyoue/daily-stock-ai:latest`
3. 拉不动就走路线 A（ghcr 超时是常态，不要硬磕）

### 飞牛注意事项
- **时区**：compose 已带 `TZ=Asia/Shanghai`，勿删——早报 08:00 / 复盘 17:00 全靠它
- **存储**：整个部署目录放 `/vol1/docker/...`，文件管理可见；mysql 默认命名卷，想直观备份可改 bind 挂载（compose 里有注释示例）
- **资源**：内存 ≤8G 的机器，保持 compose 里 `innodb-buffer-pool-size=256M`
- **备份**：飞牛"计划任务"每日跑 mysqldump（见第 4 节），或开启目录快照

## 2. 宝塔面板

推荐形态：**Docker 起服务 + 宝塔 nginx 反代 + SSL**（对外只开 80/443）。

1. 宝塔软件商店安装 **Docker 管理器** 插件
2. 导入镜像（同飞牛路线 A）或配置镜像加速后拉取
3. 准备目录（如 `/www/docker/daily-stock-ai/`），上传 `docker-compose.yml`，建 `.env`
4. Docker 管理器 → **Compose 项目** → 创建并启动
5. 宝塔**网站** → 添加站点（反向代理）→ `http://127.0.0.1:8000` → 配 SSL 证书
6. 建议给站点开 **Basic Auth**（在无应用层口令前的鉴权兜底，见审查报告 P0-4）

### ⚠️ 宝塔注意事项
- **端口冲突**：宝塔自带 MySQL 占 3306——compose 里的 mysql **不要映射宿主端口**（模板已不映射）
- **防火墙**：反代形态只开 80/443；若直连调试再放行 8000
- 用宝塔 MySQL 替代容器 MySQL 也可以，但要自己建库（utf8mb4）并改 `DATABASE_URL`，个人不建议——多一层耦合

## 3. 首次启动与验证

```bash
cd <部署目录>
cp .env.example .env && vi .env     # 填 DB_ROOT_PASSWORD / DB_PASSWORD / LLM_API_KEY
docker compose up -d
docker compose ps                    # 全部 healthy
curl http://localhost:8000/api/health
```

- 首次全量采集（20 年 K 线 + 10 年财务）：网页右上角"手动触发采集"，首轮耗时较长，在"任务监控"页看进度
- 时区自检：`docker exec dsa-app date` 应显示 CST（+08），不是 UTC

## 4. 备份

```bash
# 每日 mysqldump（飞牛计划任务 / 宝塔计划任务，保留 7 天）
docker exec dsa-mysql mysqldump -udsa -p"$DB_PASSWORD" daily_stock_ai \
  | gzip > /vol1/backup/dsa_$(date +%F).sql.gz
```
- `data/` 目录（指标缓存、导出文件）可不备份，缓存可重建
- 升级前手动备份一次

## 5. 升级流程

- 路线 A：Actions 下载新 tar → 导入镜像 → `docker compose up -d`
- 路线 B/C：`docker compose pull && docker compose up -d`
- 有破坏性变更（表结构变更）时先看 release note + 备份

- app（后端+前端，唯一对外端口 8000）+ mysql（不映射宿主端口）；redis 可选（默认不启用）

### 8.4 安全
- 访问口令：应用层登录口令（一期单用户），或反代 Basic Auth 兜底

### 8.5 备份
