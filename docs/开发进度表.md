# DailyStockAI 开发进度表

> 版本：v1.0 · 2026-11-03  
> 适用：单人开发节奏；总计约 **33 个工作日 ≈ 6~7 周**（含缓冲）

## 二、详细任务分解

### 阶段 0 · 项目脚手架 + CI/部署链路（2~3 天）
| # | 任务 | 产出 | 工时 |
|---|---|---|---|
| 0.1 | 仓库结构（backend/ frontend/ docs/），FastAPI + Vite 骨架跑通 | 空应用可启动 | 0.5d |
| 0.2 | Dockerfile（Python + Node.js≥18 + TA-Lib C 库）、docker-compose.yml、.env | 单镜像本地可起 | 1d |

**验收**：Actions 产出镜像与 tar → 飞牛导入启动 → 登录进入 → `/api/health` 200 → `docker exec dsa-app date` 显示 CST。

### 阶段 1 · 数据层 + 采集框架（5~7 天）

|---|---|---|---|

## 五、风险与缓冲

| 风险 | 影响 | 预案 |
|---|---|---|
| pywencai/问财联调反复（cookie、改版） | 阶段 1/6 延期 | 先做降级路线保主线，问财线单独收尾；不阻塞 M2 |
| LLM 报告 Prompt 调优耗时不可控 | 阶段 7 延期 | 预留 2 天机动；先保证"出报告"再追求质量 |
| 回测口径（复权/退市股）复杂度被低估 | 阶段 5 延期 | 工时已放宽；必要时先交付简化撮合，滑点/停牌后补 |
| 免费数据源突发失效 | 采集线受阻 | 接口配置化随时换源（核心兜底设计） |
| 总体延期 > 3 天 | 上线推迟 | 砍"非核心"：导出 PDF、资讯 LLM 精调、平板适配（不影响 M6） |

> 每阶段末留 0.5~1 天缓冲；每周五对照本表核对进度，偏差 > 2 天即启动砍需求预案。
